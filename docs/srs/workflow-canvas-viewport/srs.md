## 2. 概述

### 2.1 目的

把「拓扑画布无限撑大页面」的缺陷，转译成一组**可测量、可断言、可回归**的规格，供 `[2]` 出施工图、`[3]` 编码、`[6]` 联调、`[7]` 验收共用同一把尺子。

### 2.2 术语表（白话优先）

| 术语 | 白话解释 |
| :--- | :--- |
| 可视框 | 用户实际看到的 360px 高矩形窗口，尺寸由页面布局决定 |
| 内容画布 | X6 承载图元的大画布，可以比可视框大很多 |
| 尺寸回写 | X6 把自己的宽高写进挂载容器的内联 `style`，覆盖页面原本写好的高度 |
| 正反馈 | 容器变大 → 自动适配把图设更大 → 容器再变大，循环不停 |
| 平移 | 按住左键拖空白处移动「看图的视角」，不改变节点坐标 |
| 拖拽 | 按住节点移动「节点本身」，会改变节点坐标 |

### 2.3 现状事实（实测，非推断）

- `ReqManagementView.vue:1720-1723`：挂载容器写 `height:210px; overflow:hidden`。
- `ReqManagementView.vue:139-174`：Graph 配 `autoResize:true`、`height:210`、`panning.enabled:true`、`translating.restrict{0,0,1450,210}`、`nodeMovable:true`；**未启用 scroller**。
- `Layout.vue:275-278`：`.is-fullscreen { overflow: hidden !important }`，本路由命中全屏，整页不可滚。
- 运行时实测：`.x6-graph` 内联样式被写成 `width:49889px; height:110470px`，2 秒后变成 `51045px / 113054px`；外层卡片同步涨到 `51079 × 113130`。**尺寸持续增长，缺陷成立。**

## 3. 软件规格（每条带可验证断言）

### 3.1 尺寸规格

| 规格 ID | 规格描述 | 验证方式 |
| :--- | :--- | :--- |
| `SRS-01` | 可视框高度恒为 **360px**，宽度跟随父列自适应 | 读取 `getBoundingClientRect().height`，任意时刻为 360±1 |
| `SRS-02` | **可视框尺寸只由页面布局决定**；X6 图实例不得以任何方式改写挂载容器或其祖先的 `width/height` 内联样式 | 挂载前后对比容器 `style` 属性；3 秒连续采样宽高序列方差为 0 |
| `SRS-03` | 内容画布尺寸可以大于可视框，但其像素大小**不得成为可视框尺寸的输入** | 人为把内容画布尺寸翻倍，可视框宽高不变 |
| `SRS-04` | 窗口宽度变化只影响可视框宽度，360px 高度不随视口变化 | 在 1024 / 1440 / 1920 三种宽度下断言高度一致 |

### 3.2 滚动规格

| 规格 ID | 规格描述 | 验证方式 |
| :--- | :--- | :--- |
| `SRS-05` | 内容纵向超出时出现**纵向滚动条**，横向超出时出现**横向滚动条** | `scrollHeight > clientHeight` ⇒ `overflow-y` 可滚；`scrollWidth > clientWidth` ⇒ `overflow-x` 可滚 |
| `SRS-06` | 滚动到尽头能看到最下方 / 最右侧节点，不被裁掉 | `scrollTop = scrollHeight - clientHeight` 时断言末节点在视口内可见 |
| `SRS-07` | 内容不足 360px 时不出现无意义滚动条 | `scrollHeight <= clientHeight` 时纵向滚动条不可见 |
| `SRS-08` | 滚动条属于可视框，不得变成整页滚动条，也不得推动外层卡片 | 滚动时 `document.documentElement.scrollTop === 0`，外层卡片 `getBoundingClientRect().top` 不变 |

### 3.3 交互规格

| 规格 ID | 规格描述 | 验证方式 |
| :--- | :--- | :--- |
| `SRS-09` | 画布平移（左键拖空白）保留可用 | 拖拽后图元视口发生位移 |
| `SRS-10` | **平移不牵动原生滚动条**：拖空白前后 `scrollTop/scrollLeft` 不变 | 读取滚动偏移量前后对比 |
| `SRS-11` | 节点拖拽保留可用，且仍受既有边界约束，节点不可越界 | 拖到边界后节点坐标仍在约束范围内 |
| `SRS-12` | Ctrl / ⌘ + 滚轮缩放保留可用，缩放不改变可视框尺寸 | 缩放前后 `SRS-01` 仍成立 |
| `SRS-13` | 平移、拖拽、缩放、滚动四类手势互不串扰，不出现「拖一下页面乱跳」 | 逐项执行四类手势后逐条复验 `SRS-01/02/10` |

### 3.4 生命周期规格

| 规格 ID | 规格描述 | 验证方式 |
| :--- | :--- | :--- |
| `SRS-14` | L 级 ↔ S 级轨道切换触发重绘后，可视框仍为 360px、滚动条按新内容自动出现或消失 | 切换 3 轮，每轮断言 `SRS-01/05/07` |
| `SRS-15` | 路由离开再进入、页面刷新、Vite HMR 后不复发膨胀、不残留异常尺寸 | 各执行一次后采样 3 秒，`SRS-02` 成立 |
| `SRS-16` | 离开页面时清理尺寸监听与图实例，不产生重复监听叠加 | 反复进出 5 次，尺寸采样仍恒定，无重复回调 |

### 3.5 范围规格

| 规格 ID | 规格描述 | 验证方式 |
| :--- | :--- | :--- |
| `SRS-17` | 改动仅限画布挂载容器与 Graph 配置相关代码 | 代码 diff 不触及 `Layout.vue` 全屏样式、旁路矩阵面板结构、后端接口与数据库 |
| `SRS-18` | 不引入新依赖、不升级 X6、不改算子数据来源 | 依赖清单与数据渲染函数 diff 为空 |

## 4. 事件与手势冲突矩阵

| 用户动作 | 期望响应 | 不得发生 |
| :--- | :--- | :--- |
| 滚轮滚动 | 可视框内纵向滚动 | 整页滚动 / 可视框变高 |
| 拖滚动条 | 可视框内滚动 | 图元被意外平移 |
| 左键拖空白 | 图元视口平移 | 原生滚动条位置跳变 |
| 左键拖节点 | 节点坐标改变 | 可视框尺寸变化 / 节点越界 |
| Ctrl/⌘ + 滚轮 | 图元缩放 | 可视框尺寸变化 |
| 点击 L/S 切换 | 重绘图元 | 高度跳变、滚动条残留 |
| 窗口 resize | 宽度自适应 | 高度偏离 360px |

## 7. 回归探针口径（`[6]` 联调 / `[3]` 单测共用）

> 探针只测量，不替用户做验收放行。

1. **尺寸稳定探针**：挂载后每 200ms 采样一次可视框 `width/height`，共 15 次（3 秒），断言序列方差为 0 且 `height === 360`。
2. **回写探针**：对比挂载前后容器 `style` 属性，断言不存在由 X6 追加的 `width/height` 内联值。
3. **滚动可达探针**：把 `scrollTop` 推到最大值，断言最下方节点的包围盒与可视框相交。
4. **手势隔离探针**：记录平移前后 `scrollTop/scrollLeft`，断言不变。
5. **重绘探针**：连续切换 L/S 三轮，每轮复跑探针 1。

## 9. 风险与 `[2]` 待决技术项（2026-11-06 已全部冻结）

> 下表 TD-01~05 已在 [`detail-workflow-canvas-viewport-v1.0.md`](../../design/req-management/detail-workflow-canvas-viewport-v1.0.md) §3 冻结，`[3]` 按该施工图实现；本节保留原始待决记录以便追溯。
> **冻结结论**：两层 DOM（可视框 360px / 挂载点 1450×520）+ `autoResize:false` + 原生 `overflow:auto` + 尺寸常量单点声明；新增 `TD-06` 固定内容画布为 1450×520（交互原型里的 820 仅为演示滚动条的示意值，不是生产契约）。

| 编号 | 待决问题 | 为什么要留给 `[2]` |
| :--- | :--- | :--- |
| `TD-01` | 如何切断「X6 回写尺寸 → ResizeObserver 正反馈」：关闭 `autoResize`、改由外层 wrapper 承载尺寸，还是二者组合 | 属实现手段，需看 X6 版本能力与现有代码耦合度 |
| `TD-02` | 滚动条由原生 `overflow` 承担，还是引入 X6 scroller 插件（当前 `package.json` 未装该插件） | 涉及是否新增依赖，须过「零新依赖」红线评审 |
| `TD-03` | 360px 常量声明位置（组件常量 / 样式类 / CSS 变量），以及如何让 `translating.restrict` 的既有 210 高度约束同步更新 | 属施工图细节 |
| `TD-04` | 平移手势与滚动事件如何隔离（事件拦截 / 手势判定 / 配置开关） | 依赖 `TD-01/02` 的选型结果 |
| `TD-05` | 既存 `height:210` 与 `translating.restrict{height:210}` 是否一并调整为 360，避免节点被约束在旧高度内看不到 | 需确认约束语义是「可视框」还是「内容边界」 |

**已识别风险**：若只改容器 CSS 而不切断尺寸回写，正反馈仍会复发（当前源码已写死 210px 却照样膨胀，即为反例）；这是本需求最容易踩的坑。
