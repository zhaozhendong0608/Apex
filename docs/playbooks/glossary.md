# 📖 工作流专有名词表 (Glossary)

| 术语 | 分类 | 一句话解释 | 使用场景（什么时候用 / 你该做什么） | 在哪出现 |
| :--- | :--- | :--- | :--- | :--- |
| `[0]` 总览 | 指令 | 打印三条轨道的指令表 | 刚接手项目、或不知道某个阶段该走哪条指令时 → 发 `0` | `00-sop-overview.md` |
| `[1]` 规划 | 指令 | 一句话需求 → 澄清 → PRD/SRS/TC → 拆 Task | 老板丢来一句"加个告警"、你也还没想清要什么 → 发 `1`，让它用选择题把需求逼出来 | `01-sop-planning.md` |
| `[1+]` 大模块 | 指令 | 在 `[1]` 之上追加交互原型 | 需求涉及新页面 / 新菜单 → 发 `1+`；纯后端接口不需要 | `01-sop-planning.md` |
| `[2]` 技术方案 | 指令 | 写施工图，冻结契约与表结构 | 动手写代码**之前**；或接口字段要改时（必须先改文档） | `02-sop-tech-design.md` |
| `[3]` 编码 | 指令 | TDD 红→绿→重构 | 契约冻结后，一个 Task 一轮 → 发 `3` | `03-sop-coding.md` |
| `[4]` 门禁 | 指令 | 跑 `gate.py` 让机器判 | 一个 Task 写完、准备合入前 → 发 `4` | `04-sop-code-review.md` |
| `[5]` 评审 | 指令 | 人来看机器判不了的部分 | 门禁 `[LGTM]` 之后、集成之前（L 级必做） | `05-sop-review.md` |
| `[6]` 集成 | 指令 | 真实拓扑跑 TC + E2E | 一个模块的所有 Task 都做完后 → 发 `6` | `06-sop-integration.md` |
| `[7]` 验收 | 指令 | 唯一归档出口 | 集成绿了、你确认功能对 → 发 `7` 标绿收尾 | `07-sop-acceptance.md` |
| `[8]` 部署 | 指令 | 离线容器编排 | 要交付到内网环境时；日常开发不用 | `08-sop-deploy.md` |
| `[9]` 发布 | 指令 | 提交规范、Tag、三级回滚 | 一个里程碑做完要发版时 | `09-sop-git-release.md` |
| `[B1]` 老项目破局 | 指令 | 只扫前 3 层，建切片地图 | 第一次接手别人写的项目、找不到从哪下手时 → 发 `B1` | `B1-sop-legacy.md` |
| `[B2]` 快修 | 指令 | ≤20 行单文件微创 | 改文案、换颜色、加个判空这种"顺手一下" → 发 `B2` | `B2-sop-fasttrack.md` |
| `[B3]` 开发排错 | 指令 | 小黄鸭根因定位 | 本地跑报错、控制台一片红 → 发 `B3` + 粘贴完整堆栈 | `B3-sop-debug.md` |
| `[B4]` 线上排障 | 指令 | 先保现场再修 | 已部署环境出故障（OOM、队列积压、接口 500） | `B4-sop-troubleshoot.md` |
| `[B5]` 归档 | 指令 | 压缩会话、落盘交接 | 今天不干了 / 要换话题 / 聊了 20 轮 AI 开始健忘 → 发 `B5` | `B5-sop-archive.md` |
| `[B6]` 恢复 | 指令 | 读名片复活断点 | 第二天开工第一句；或换窗口、换人接手 → 发 `B6` | `B6-sop-resume.md` |
| 主链 | 概念 | `1→2→3→4→5→6→7`，推进任务状态 | 判断"这一步要不要改看板"时：数字会改，`B` 开头不会 | `.cursorrules` |
| 交付链 | 概念 | `8→9`，里程碑级 | 只有当模块要"交付给客户/上线"时才走 | `.cursorrules` |
| 旁路 | 概念 | `B1~B6`，不改 ACTIVE | 写到一半报错、要顺手改个样式、临时接老项目 | `.cursorrules` |
| Task | 状态 | 15~30 分钟可验证的原子任务 | 看板里每个方括号；发 `[3]` 时 AI 一次只处理一个 | `tier3_status.md` |
| ACTIVE | 状态 | 当前唯一焦点任务 | 发 `[3]` 前先 `board.py list`：有且只有一个 ACTIVE 才对 | `tier3_status.md` |
| TODO | 状态 | 排队等待的任务 | 规划完看到一串 TODO；`complete` 后会自动把第一个拉成 ACTIVE | `tier3_status.md` |
| DONE | 状态 | 已验收归档的任务 | 想看"做到哪了"就看这一区；带完成日期 | `tier3_status.md` |
| 单焦点 | 规则 | 同时只允许一个 ACTIVE | `start` 报了"当前已有 ACTIVE"时：先 `[7]` 归档旧的，别硬切 | `board.py` |
| 锚点 | 技术 | `<!-- SECTION:XXX -->` 区块标记 | 有人想手改看板时——别改，锚点坏了脚本就定位不到 | `tier3_status.md` |
| 状态机 | 概念 | 任务只能经 `board.py` 流转 | 任何时候想改任务状态：只能跑脚本，不许手改文件 | `.cursorrules` |
| 看板 | 文件 | 状态机唯一事实源 | `[3]` 前看焦点、`[7]` 后看是否标绿 | `tier3_status.md` |
| tier1 名片 | 记忆层 | 27 行快照：身份+焦点+里程碑 | `[B6]` 复活时 AI 最先读的就是它；你也能 3 秒想起"干到哪了" | `tier1_snapshot.md` |
| tier2 模块地图 | 记忆层 | 自动扫描的模块索引 | `[1+]` 开新模块前，先看有哪些模块、四件套齐不齐 | `tier2_modules.md` |
| tier2 老项目图谱 | 记忆层 | 四维切片：路由/文件/API/表 | 只有跑过 `[B1]` 才有内容；新项目里显示"未启用"是正常的 | `tier2_legacy_arch.md` |
| tier3 看板 | 记忆层 | 热数据：当前任务状态 | 每轮 `[3]` / `[7]` 都会读写；别整份读，看 ACTIVE 那一段就够 | `tier3_status.md` |
| tier3 黑匣子 | 记忆层 | 冷数据：只追加的交接日志 | 想知道"上周为什么改了这个字段"→ 翻这里；超 300 行会提示轮转 | `tier3_handover.md` |
| 派生视图 | 概念 | 由脚本重算的文件 | 想改 `tier1` 或 `tier2_modules` 时——别手写，改源头让脚本重算 | 记忆层 |
| 条件资产 | 概念 | 只在特定指令下才生成 | 在 `tier2_legacy_arch` 里看到"未启用"，不用管它 | 记忆层 |
| gate.py | 工具 | 统一质量门禁 | `[4]` 时由 AI 调用；你也可以手动 `python3 .ai/scripts/gate.py --staged` | `.ai/scripts/gate.py` |
| LGTM | 门禁 | 全部通过（退出码 0） | 看到它才能发 `[5]`；没看到就是没过 | `gate.py` |
| BLOCKING | 门禁 | 有阻断项（退出码 1） | 出现了就**不许合入**，按清单逐条修完重跑 `[4]` | `gate.py` |
| exit 2 | 门禁 | 空变更集/用法错误 | 看到 exit 2 说明门禁根本没跑——**别当通过**，先 `git add` | `gate.py` |
| 看门狗 | 概念 | 一组自动化底线规则 | AI 说"我写完了"时，用它来验证（最小改动/无假数据/无新依赖） | `02-sop-coding.md` |
| 8 底线 | 规则 | 编码阶段 8 条硬约束 | 写码前默念一遍；其中 6 条已由 `gate.py` 自动查 | `02-sop-coding.md` |
| 密钥扫描 | 门禁 | 拦截硬编码密码/Key | 改配置文件、写测试脚本时会被它拦下 → 挪到 `.env` | `gate.py` |
| SQL 回滚配对 | 门禁 | 每个升级脚本要配回滚脚本 | 改了表结构就会触发；缺 `rollback_*.sql` 直接 BLOCKING | `gate.py` |
| 元门禁 | 门禁 | 检查工作流自身 | 改完 `.ai/` 或文档后跑一次 `gate.py --meta` 确认没搞坏 | `gate.py --meta` |
| 引用完整性 | 门禁 | 检查指令号是否都有对应 SOP | 重命名/重编号后必跑；旧编号残留会被它抓出来 | `gate.py --refs` |
| 能力点基线 | 门禁 | 91 条冻结能力 | 想"精简一下 SOP"时：删字可以，删能力点会被拦 | `_capability-baseline.md` |
| PRD | 文档 | 谁在什么场景要什么 | `[1]` 产出；**你要逐条确认业务规则**，这里是返工成本最低的地方 | `docs/modules/<m>/` |
| SRS | 文档 | 把 PRD 翻成可开发粒度 | `[1]` 产出；AI 写代码时对着它，你一般不用改 | `docs/srs/<m>/srs.md` |
| TC 用例矩阵 | 文档 | 业务/UI/异常三类用例 | `[1]` 就要就绪；`[6]` 集成时逐条执行，**没它就等于没测** | `docs/test-cases/` |
| TD / detail.md | 文档 | 契约、表结构、时序流 | `[2]` 产出并冻结；之后改字段必须先改它 | `docs/design/<m>/` |
| mockup.html | 文档 | 可点击原型（三态齐全） | `[1+]` 产出；**你照着点一遍**，不对就当场让 AI 改 | `docs/modules/<m>/` |
| 契约冻结 | 规则 | 定稿后不许随手改字段 | 想临时加个参数时——先改 `detail.md` 再改代码 | `[2]` |
| DDL / rollback | 文档 | 建表脚本 + 回滚脚本 | 上线前必须确认成对且非空，出事就靠它回退 | `docs/db/migrations/` |
| Pizza 切片 | 方法 | 切成 S1/S2/S3 三层原子任务 | `[1]` 拆任务时看这个：骨架→业务→测试桩 | `[1]` |
| 双轨并行 | 方法 | 研发轨与测试轨同源启动 | `[1]` 规划时就要把 TC 一起产出，别等写完代码再想怎么测 | `[1]` |
| S/M/L 分级 | 方法 | 按改动面决定流程深度 | 需求一到手先定级：S 走 `[B2]`、M 可省原型、L 一步不许少 | `00-sop-overview.md` |
| 批处理 | 方法 | `1+2` / `1+2+3` 合并沟通轮次 | 需求明确、不想来回确认时；但落盘文档一份不能少 | `[1]` |
| 返工回路 | 方法 | 不合格回缺陷节点，重跑下游门禁 | 原型/契约/代码被打回时看 Playbook §3，**别在下游打补丁** | Playbook §3 |
| 黑匣子 | 产物 | 带时间戳的交接记录 | `[7]` 归档时自动写；追溯历史决策时翻它 | `tier3_handover.md` |
| 踩坑卡片 KI | 产物 | 复盘出的 `postmortem-*.md` | 同一个坑踩第二次之前，先搜一下有没有现成卡片 | `knowledge-cards/` |
| 锁死探针 | 产物 | 钉住老代码行为的反向测试 | 改老模块时先跑它：全绿说明你没改崩旧逻辑 | `scripts/tests/test_legacy_*.py` |
| Mermaid | 技术 | 页面里的流程图语法 | 看 Playbook / 总览面板的图；离线也能渲染（本地 `assets/`） | `workflow_guide.html` |
