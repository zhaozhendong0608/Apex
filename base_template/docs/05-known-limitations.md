### 🟢 [BUG-007] `board.py` 与 Markdown 的脆弱正则表达式绑定
- **状态**: 🟢 已解决 (RESOLVED)
- **发现日期**: 2026-08-08
- **解决日期**: 2026-08-09
- **毒舌诊断**: **“用最炫酷的 Python 脚本，去操控最脆弱的文本格式”**。任务状态机（ACTIVE/TODO/DONE）强依赖 Python 脚本中的正则语法去匹配 Markdown 文件。只要人类或 AI 不小心手动修改了标题层级、空格或 Emoji，脚本立马报错卡死。没有任何原子锁或数据库一致性保障，本质上是“自嗨式的伪自动化”。
- **影响范围**: 所有基于 `board.py` 的任务切片状态流转。
- **修复说明**: 重构升级了 `board.py` 定位算法，上线**“HTML 注释锚点法 (Comment Anchor Protocol)”**。在 Markdown 隐式嵌入物理锚点并追加自动自愈 (Self-Healing) 逻辑，解耦了正则表达式对标题层级和文本样式的依赖，成功解决了正则绑定卡死问题！

### 🟢 [BUG-008] 老项目 `arch.py` 浅层扫描产生的“架构安全感假象”
- **状态**: 🟢 已解决 (RESOLVED)
- **发现日期**: 2026-08-08
- **解决日期**: 2026-08-09
- **毒舌诊断**: **“扫描只看皮囊，业务全在盲区”**。`arch.py tree 3` 只能粗暴扫描前 3 层文件树。在真实的 legacy 老项目中，恶心的耦合逻辑往往埋藏在第 5 层甚至更深的目录、各种动态反射或复杂的微服务依赖里。这种浅层扫描除了给开发者提供“我已吃透架构”的心理安慰外，在应对真实业务交织时依然是一团迷雾。
- **影响范围**: 复杂单体老项目接入（`[0]` SOP）。
- **修复说明**: 正式上线**“路由切入 + 4D元数据池 + 拓扑关系图谱 (Obsidian 范式)”**。升级了 `arch.py`（支持 `find` 深度穿透搜寻与 `analyze` 元数据自动建图），并在 `docs/06-legacy-graph-analysis.md` 中沉淀了工业级指南，彻底清除了浅层扫描产生的伪安全感！

### 🟢 [BUG-009] 看门狗“单次改动 ≤3 文件”在大规模重构场景下的卡死
- **状态**: 🟢 已解决 (RESOLVED)
- **发现日期**: 2026-08-08
- **解决日期**: 2026-08-09
- **毒舌诊断**: **“给大象戴手铐，迫使 AI 产生中间态垃圾代码”**。看门狗护栏硬性限制单次编码只能改动 3 个文件。但在真实的数据库 ORM 变更、全局接口重构或类型定义修改时，往往需要同时联动 5~10 个文件。强制切碎改动迫使 AI 提交编译不通过的中间代码，或者频繁打卡归档，反而拉长了风险窗口期。
- **影响范围**: 全局架构重构、数据库字段重命名、跨模块 API 变动。
- **修复说明**: 放弃了死的数量硬限制，全面升级上线**“最小改动原则 (Minimum Surgery Protocol)”**。解除了死扣文件个数的教条枷锁，同时严格约束 AI 外科手术式修改，**严禁凭 AI 想象力多写代码或自作主张重构无关模块**，完美解决了大规模重构卡死问题！
