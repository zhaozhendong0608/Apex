# 📐 架构设计说明书与变更同步规约 (Change Sync Protocol)

## 📌 1. 修订历史 (Revision History) 追加规约

每次对已落盘的 HLD 或 DLD 进行增量修改时，必须在文档顶部的 **【文件修订页】** 表格中**物理追加一行记录**：

1. **版本号升号规则**：
   - 第一次生成为 `V0.1`（草案）➔ 评审通过发布 `V1.0`（基线）。
   - 小需求变更/字段追加 ➔ `V1.1` / `V1.2`。
   - 重大架构调整/重构 ➔ `V2.0`。
2. **格式规范**：
   ```markdown
   | 编号 | 章节名称 | 修订内容描述 | 修订日期 | 修订版本 | 修订人 |
   | :--- | :--- | :--- | :--- | :--- | :--- |
   | 1 | 所有章节 | 初始版本创建 | 2026-06-09 | V1.0 | AI Agent |
   | 2 | 6.2 表结构设计 | 增加 user_status 软删除字段 | 2026-06-10 | V1.1 | AI Agent |
   ```

---

## 🛠️ 2. 增量更新 (Diff Update) 护栏铁律

1. **禁止全量覆盖**：对于已存在的详细设计文档，严禁直接删词重写整篇！
2. **定位受影响章节**：只定位受变更影响的章节（如：`4.1 接口设计`、`6.2 表结构设计`），在目标章节做局部追加或修改。
3. **高对比度 Mermaid 图表同步**：如果数据库增加了表关系，同步更新 `erDiagram`；如果流程发生了分支变动，同步更新 `sequenceDiagram`。
